PART 1講義

ソケットとは何か

話すのは4点だけです。用語の網羅はしません。

1-1　科目の進め方

  • 毎回、講義 → 演習 → 課題提示の順で進みます。
  • 課題は毎回出ます。すべて出力形式が厳密に決まった CLI プログラムで、採点スクリプトによる自動判定を行います。
  • 採点スクリプトは、あなたにも配布されます。提出前に手元で、教員と同じ判定を実行できます。「提出したら落ちていた」は起こりません。
  • 通信相手は原則 localhost。ポートは 40001 以降のみを使います。

1-2　4層と、今日書く層

TCP/IP の4層のうち、この授業で書くのはアプリケーション層だけです。重要なのは各層の名前ではなく、下の層に何を任せているかです。

層この授業での扱い
アプリケーション層ここを書く。第2回以降13回まで、ずっとここ
トランスポート層(TCP/UDP)使う。Socket を作った時点で、順序保証と再送は任せている
インターネット層(IP)宛先まで運ぶのは任せる。今日はIPアドレスを見るだけ
ネットワークインタフェース層この授業では扱わない
★ この回で、いちばん覚えておくこと。

new Socket(host, port) の1行は、「名前を引き、経路を決め、3ウェイハンドシェイクをし、以後の順序保証と再送を引き受ける」という膨大な処理を呼び出しています。今日この1行が失敗する3通りを体験することが、本日の中心です。

1-3　ソケット＝(IPアドレス, ポート番号)

この2枚の図を、あとで見返せるようにしておいてください。第2回以降、「ポートって何だったか」と思ったら、まずここに戻ります。

図1　IPアドレスは「どのPCか」、ポート番号は「そのPCの中のどのプログラムか」。この2つの組み合わせをソケットと呼びます。演習Aの netstat で見た LISTENING の行は、この左側の口が今いくつ開いているかの一覧です。

図2　通信は「4つ組」で識別される。だから同じサーバに何人が同時につないでも混ざりません。接続する側のポート番号(54321)は、自分で決めていません。OSが空いている番号を自動で割り当てます。

  • 0〜1023 はウェルノウンポートで、多くのOSでは使用に管理者権限が要ります。この授業では使いません。演習・課題とも 40001 以降だけを使います。
  • localhost ／ 127.0.0.1 は自分自身を指します。図1のPCが、送る側と受ける側を兼ねている状態です。今日の通信はすべてPCの中で完結します。
  • 同じポートを、2つのプログラムが同時に LISTEN することはできません。第3回で BindException として出会います。
ひとこと：なぜ 1024 未満を使わないのか。ポート番号は 0〜65535 の範囲で、用途によって3つに分かれています。この授業が 40001 番台を使うのは、好みではなく、管理者権限がないからです。
範囲呼び方性格
0 〜 1023ウェルノウンポート番号と役割が世界中で決まっている。HTTP は 80、HTTPS は 443、SSH は 22。ブラウザに https://example.com と打つだけでつながるのは、「HTTPS なら 443」が暗黙の了解になっているから
1024 〜 49151登録済みポート主要なソフトウェアが申請して押さえている番号帯。空いている番号は自由に使える。この授業で使う 40001 はここ
49152 〜 65535動的・一時ポートOSが自動で割り当てる番号帯。図2の 54321 がこれ。接続する側は、この中から勝手に1つ選ばれる
★ ウェルノウンポートが「決まっている」ことの意味。

80番や443番を、誰でも自由に使えてしまうと困ります。先に起動したプログラムが 443 番を押さえれば、そのPCに来た HTTPS の通信をすべて受け取れてしまうからです。そのため多くのOSは、1024 未満のポートで待ち受けるのに管理者権限を要求します。

この教室のPCに管理者権限はありません。だからこの授業では 1024 未満を一切使いません。制約というより、「ポート番号には社会的な取り決めがある」ことの裏返しだと思ってください。
★この授業が 40001 を選んだ理由。1024 未満は管理者権限がないため使えず、49152 以上はOSの自動割り当てとぶつかる可能性がある。その両方を避けた、真ん中の帯です。

それでも Address already in use が出たら、前に起動した EchoServer がまだ生きています。そのウィンドウで Ctrl＋C を押してください。番号を変える必要はありません。

1-4　★ GitHub Copilot の使い方ルール

★Copilot は使って構いません。禁止しません。ただし、この授業の評価は「動いたか」ではなく「説明できるか」で行います。提出コードの任意の行について、口頭で説明を求めることがあります。

Copilot 4つのルール

  • Tab を押す前に、提案を読む。読まずに押した行は、自分のコードではありません
  • プロンプトを記録する。課題の提出物に prompt_log.md が含まれます
  • 学籍番号・氏名・パスワード・未公開の配布資料を入力しない
  • 生成されたコードが動いても、期待した理由で動いているとは限らない。必ず自分で実行して確認する
★ ネットワークのコードで、Copilot が特に間違えるところ

・タイムアウトを設定しないコードを平気で出します。new Socket(host, port) はタイムアウトを指定できません。今日の課題では connect() を使わせます
・例外を catch (Exception e) でまとめてしまいます。今日の学習内容は「例外を3種類に区別すること」そのものなので、これをやると課題が通りません
・文字コードを指定しないコードを出します。第2回で必ず問題になります

演習A：自分のPCを観察する

まだ Java を書きません。コマンドで、今このPCが持っているアドレスと、開いているポートを見ます。

A-1　実行するコマンド

Windows は PowerShell、macOS / Linux は Terminal。4つとも実行し、出力を手元に控えてください。

ipconfig自分の住所

macOS / Linuxifconfig または ip addr

自分のIPv4アドレスを見つけて控えてください。192.168. や 10. で始まっていれば学内ネットワーク内のアドレスです。

ping localhost自分自身に届くか

4回応答が返ればOKです。これが返らない場合、この後の演習はすべて失敗します。その場合はすぐTAを呼んでください。

nslookup www.doshisha.ac.jp名前をIPに変える

返ってきたIPアドレスを控えてください。演習Bで、Java が出した結果と突き合わせます。

netstat -an今開いているポート

Windowsnetstat -an | findstr LISTENING

macOS / Linuxnetstat -an | grep LISTEN

LISTENING と表示されている行が、「誰かの接続を待っているプログラム」です。ポート番号をいくつか控えてください。

A-2　考えること(ここが本題)

① LISTENING の行は何個ありましたか。そのポート番号のうち、1024未満のものはいくつありますか
② 40001 は一覧にありましたか。(ないはずです。だから今日これから使えます)
③ ping localhost の応答時間は何ミリ秒でしたか。この数字を覚えておいてください
③を控える理由。演習Cで、同じ localhost への接続にかかった時間を測ります。ping の値と近い桁になるはずです。通信にかかる時間は、相手までの距離で決まります。この感覚は、第10回のタイムアウト設計でそのまま使います。
★ここまで、まだ Java を1行も書いていません。それで正しい進度です。

PART 4演習C

演習C：接続を失敗させ、次に成功させる

この演習が今日の中心です。先に失敗させます。

C-1　まず、失敗させる

ファイル名 Connect.java。まだサーバは起動しません。誰も待っていないポートに接続を試みます。

import java.net.*;

public class Connect {
  public static void main(String[] args) {
    String host = args[0];
    int port = Integer.parseInt(args[1]);

    long start = System.currentTimeMillis();
    try (Socket socket = new Socket()) {
      socket.connect(new InetSocketAddress(host, port), 2000);
      System.out.println("CONNECTED");
    } catch (UnknownHostException e) {
      System.out.println("UNKNOWN_HOST");
    } catch (SocketTimeoutException e) {
      System.out.println("TIMEOUT");
    } catch (ConnectException e) {
      System.out.println("REFUSED");
    } catch (Exception e) {
      System.out.println("ERROR: " + e.getClass().getSimpleName());
    }
    System.out.println("ELAPSED_MS=" + (System.currentTimeMillis() - start));
  }
}
このコードは、あえて配布します。Copilot に書かせると、new Socket(host, port) というタイムアウトを指定できない書き方を高い確率で提案してくるためです。まずこの形を体に入れてから、Copilot に頼んでください。

C-2　3種類の失敗を、順に起こす

失敗は「どの段階まで進んで止まったか」で3種類に分かれます。下の図を見てから、3つのコマンドを順に実行してください。

図3　接続が失敗する3通り。ELAPSED_MS の値が、そのまま「どこで止まったか」の手がかりになります。課題 NetProbe.java の問3は、この3つを区別して出力する問題です。

実行するコマンド出るはずの結果なぜそうなるか
java Connect localhost 40001REFUSEDそのPCは存在するが、そのポートで誰も待っていないので、即座に拒否が返る
java Connect no-such-host.invalid 40001UNKNOWN_HOST名前がIPに変換できない。接続以前の段階で失敗している
java Connect 10.255.255.1 40001TIMEOUT宛先まで到達できず、拒否も返ってこないので、2秒待って諦める
★ ELAPSED_MS の値を3つ並べて比べてください。REFUSED はごく短く、TIMEOUT はほぼ 2000 になります。この差が、「拒否された」と「返事がない」の違いです。
3つ目が TIMEOUT にならない環境があります。学内ネットワークの構成によっては即座に別のエラーになることがあります。その場合は ERROR: で出た例外クラス名を控えてください。環境によって結果が変わること自体が、ネットワークの実際です。

C-3　次に、成功させる

配布した EchoServer.jar を、自分のPCで起動します。ターミナルをもう1枚開いてください。

# ターミナル①（このまま起動しっぱなしにする）
java -jar EchoServer.jar 40001

# ターミナル②（別ウィンドウで実行する）
java Connect localhost 40001
① ターミナル② に CONNECTED が出る
② もう一度 netstat を実行すると、40001 が LISTENING に現れている
③ ターミナル① を Ctrl＋C で止めると、再び REFUSED に戻る
★ ②を飛ばさないでください。演習Aで一覧になかったポート 40001 が、自分がプログラムを起動したことで一覧に現れます。そして止めればまた消えます。

LISTEN とは、「そのポートで待っているプログラムが、今この瞬間に動いている」という状態のことです。文章で読むより、この往復を1回やるほうが速く分かります。

PART 5演習D

演習D：やりとりされたバイト列を見る

「文字列を送っている」と思っているものが、実際には何なのかを確認します。

★ この授業では Wireshark を使いません。パケットキャプチャにはドライバの導入が必要で、管理者権限のない環境では利用できないためです。代わりに、自分のプログラムが送受信したバイト列を、自分で16進表示します。見える範囲は狭くなりますが、「自分が書いた行が、何バイトになったか」は完全に分かります。

D-1　作るもの

Connect.java を Dump.java としてコピーし、接続成功後に1行送って、返ってきたものを16進で表示するよう変更します。

D-2　Copilot への指示

// 接続に成功したら、UTF-8 で "HELLO\n" を送信する。
// 返ってきたバイト列を最大64バイト読み取り、
// 1バイトずつ "%02X " の形式で16進表示する。
// そのあと、同じバイト列を UTF-8 の文字列としても表示する。
期待される出力(例)
HEX: 48 45 4C 4C 4F 0A
TEXT: HELLO

D-3　★ ここで気づいてほしいこと

見るもの気づくこと
0A改行は1バイトの文字である。目には見えないが、確かに送られている
6バイト"HELLO" は5文字だが、送られたのは6バイト。文字数とバイト数は違う
日本語を送ると1文字が3バイトになる。ここが第2回の主題です
★時間が余った人は、送信する文字列を日本語に変えてみてください。バイト数が何倍になるか、実際に数えてから第2回に来ると理解が速くなります。
演習Dが動いていなくても、PART 6 が始まったら手を止めてください。演習Dは課題の必須要素ではありません。ここで粘って課題の説明を聞き逃すほうが、はるかに損です。

課題：NetProbe.java（全5問）

ホスト名とポート番号を受け取り、接続を試みた結果を、決められた形式で標準出力に出すプログラムを作ります。1問につき出力が1行ずつ増えます。ファイルは1つだけで、問ごとに新しく作らず、同じ NetProbe.java を育てていきます。

完成形

java NetProbe <ホスト名> <ポート番号>
HOST=localhost
ADDR=127.0.0.1
PORT=40001
RESULT=CONNECTED
ELAPSED_MS=3
問やることこの問で増える行
問1引数を受け取り、そのまま出力するHOST= / PORT=
問2名前解決して ADDR= を足すADDR=
問3接続して RESULT= を4種に分けるRESULT=
問4所要時間を測り、出力を5行そろえるELAPSED_MS=
問5自己採点を通し、記録を添えて提出する4 / 4 passed
全問に共通。どの入力でもスタックトレースを出さず、正常終了すること。
問1引数を受け取り、そのまま出力する

やること

  • コマンドライン引数を2つ受け取る
  • 第1引数を HOST= に、第2引数を PORT= に出す
  • 受け取った文字列を加工しない（そのまま出す）
  • まだ接続もしないし、名前解決もしない

実行例

> java NetProbe localhost 40001

HOST=localhost
PORT=40001
ここでつまずく
引数が2つ渡されなかったときに、配列の範囲外で落ちないこと。何も渡されなくても、正常終了させます。
問2名前解決して ADDR= を足す

やること

  • InetAddress.getByName() で第1引数を解決する
  • 解決できたら、そのIPアドレスを ADDR= に出す
  • UnknownHostException なら ADDR=-（半角ハイフン1文字）
  • 出力の順番は HOST → ADDR → PORT

実行例

> java NetProbe localhost 40001
HOST=localhost
ADDR=127.0.0.1
PORT=40001

> java NetProbe no-such-host.invalid 40001
HOST=no-such-host.invalid
ADDR=-
PORT=40001
ここでつまずく
例外を throws で呼び出し元に逃がさないこと。自分で catch して ADDR=- を出します。演習Bで直したのと同じ箇所です。
問3接続して RESULT= を4種に分ける

やること

  • Socket() を作り、connect(アドレス, 2000) で接続する
  • 成功したら CONNECTED
  • UnknownHostException → UNKNOWN_HOST
  • ConnectException → REFUSED ／ SocketTimeoutException → TIMEOUT

実行例

> java NetProbe localhost 40099
HOST=localhost
ADDR=127.0.0.1
PORT=40099
RESULT=REFUSED

※ RESULT に出る値はこの4種のみ
   CONNECTED / UNKNOWN_HOST / REFUSED / TIMEOUT
★ここが課題の中心。2つとも落としやすい。
catch (Exception e) でまとめないこと。もう1つは catch の順番で、広い例外を先に書くと後ろの catch に到達しません。
問4所要時間を測り、出力を5行そろえる

やること

  • 接続を始める直前に System.currentTimeMillis() を記録
  • 終わったあとの差を ELAPSED_MS= に整数で出す
  • どの入力でも、出力はちょうど5行にする
  • ポート番号が数値でないときも落ちずに終了する

実行例

> java NetProbe 10.255.255.1 40001
HOST=10.255.255.1
ADDR=10.255.255.1
PORT=40001
RESULT=TIMEOUT
ELAPSED_MS=2001

※ ELAPSED_MS の値は採点で見ません
ここでつまずく
デバッグ用に入れた System.out.println の消し忘れ。採点スクリプトが 出力が 6 行 として落とします。
問5自己採点を通し、記録を添えて提出する
