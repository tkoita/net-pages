PART 1講義

待つ側の4つの動詞

1-1　クライアントとサーバは、何が違うのか

コードの上での違いは、1つだけです。

やること使うクラス
クライアントこちらから相手を指定して、つなぎに行くSocket
サーバ番号を確保して、誰かが来るのを待つServerSocket ＋ Socket

サーバ側だけが、クラスを2つ使います。 ここが今日いちばん混乱しやすいところなので、先に図で押さえます。

図1　ServerSocket は「受付」、Socket は「通話中の1本の線」

受付（ServerSocket）は開けたまま。accept() が返すたびに、通信用の Socket が1本ずつ増えます。

★ ここだけは覚えて帰ってください。 accept() は「待つだけのメソッド」ではなく、「新しい Socket を作って返すメソッド」です。 受付（ServerSocket）は開けたままで、来た人ごとに線（Socket）が1本ずつ増えます。

Copilot は、ServerSocket から直接 getInputStream() を呼ぶコードをときどき提案します。 そんなメソッドはありません。出てきたら、提案を読まずに Tab を押した証拠です。

1-2　4つの動詞

サーバがやることは、順番に4つだけです。

図2　サーバとクライアントの時間の流れ

サーバは (1)〜(4) の順に進み、(4) のあと (2) に戻ります。クライアント側は、第1回・第2回で書いたものです。

動詞Java での書き方意味
bindnew ServerSocket(40001)その番号を、自分のものとして確保する
listen（同じ行で同時に行われる）接続の申し込みを受け付ける状態にする
acceptserver.accept()誰かが来るまで止まる。 来たら Socket を返す
closes.close() ／ server.close()1本の線を閉じる ／ 受付そのものを閉じる
accept() で止まっているサーバは、固まっているのではありません。 画面に何も出ず、キーボードも効かないので「落ちた」と思う人が毎年います。それが正常な待機状態です。 第1回で EchoServer.jar を起動したターミナルが固まって見えたのは、これです。

1-3　同じ番号は、1つのプログラムしか確保できない

第1回でこう書きました。

同じポートを、2つのプログラムが同時に LISTEN することはできません。第3回で BindException として出会います。

今日、そこに着きます。 演習Bで、わざと2つ起動して出します。

この決まりがあるから、ポート番号は「宛先」として働きます。 40001 番に届いたものをどのプログラムに渡すかを、OS が迷わずに決められるのは、その番号を持っているプログラムがいつも1つだけだからです。

1-4　new ServerSocket(port) は、どこからの接続を待つのか

そのPCの、すべての入口で待ちます。 具体的には、

  • localhost（127.0.0.1）への接続 … 自分のPCの中から
  • 自分のIPアドレス（192.168. や 10. で始まるもの）への接続 … 同じネットワークにいる他のPCから

の両方を、同じ1つの ServerSocket が受けます。netstat では 0.0.0.0:40001 または [::]:40001 と表示されます。0.0.0.0（IPv4）と [::]（IPv6）は、どちらも「どのアドレス宛でも受ける」という意味です。

演習Dで、隣のPCから実際に接続してもらいます。

1-5　★ 標準出力は「約束」、標準エラーは「ひとりごと」

今日から、サーバの出力を2つに分けます。

出力先何を出すか今日の例
標準出力（System.out）仕様で決まっているものだけLISTENING port=40001 の1行だけ
標準エラー（System.err）自分のためのログ。 ただしスタックトレースは出さない誰が接続してきたか、何を受け取ったか
★ なぜ分けるのか。 課題の採点スクリプトは、あなたのサーバの標準出力を読みます。 ここにデバッグ用の System.out.println が1行でも混ざると、採点で落ちます。

これは授業の都合ではありません。実際のサーバプログラムもそうなっています。「機械が読むもの」と「人間が読むもの」を混ぜないでください。 迷ったら System.err に出す、と覚えておけば安全です。

ただし、e.printStackTrace() は標準エラーでも使いません。 例外は System.err.println("client error: " + e.getMessage()) のように1行で出します。Copilot は catch の中に printStackTrace() をよく入れてきます。

1-6　★ この回で Copilot が特に間違えるところ

第1回からのルール（Tab を押す前に読む／プロンプトを記録する／学籍番号やパスワードを入力しない）はそのままです。Copilot の使い方そのもの（コメント → Tab、Ctrl ＋ I、/explain・/fix）は 付録 5 を見てください。そのうえで、サーバのコードでは次の4つがよく出ます。

Checklist

  • 頼んでいないのにスレッドを使ってきます。 new Thread(...) や ExecutorService が出てきたら、今日は使いません。 第4回の内容です
  • PrintWriter(socket.getOutputStream(), true) を提案してきます。 これは文字コードを指定していません。 第2回の禁則です。OutputStreamWriter(..., StandardCharsets.UTF_8) を使ってください
  • 1行読んだら終わるコードを出します。while ((line = in.readLine()) != null) のくり返しが必要です
  • 例外を捕まえて System.exit(1) を呼ぶコードを出します。クライアント1人のエラーで、サーバ全体を終了させてはいけません

1-7　答えは、まだ言いません

演習Bで作るサーバは、1人ずつ順番に相手をします。では、

1人目がつないだままのところへ、2人目がつなぎに来たら、2人目の画面には何が出るか。

スライドの「答えは、まだ言いません」のページに、1文で予想を書いてください。 正解でなくて構いません。演習Cで、自分で答え合わせをします。 そのあと課題の prompt_log.md で、理由を書いてもらいます。

1回だけ受け付けるサーバ

まず、いちばん短いサーバを動かします。 1人だけ受け付けて、1行だけ返して、終了します。

A-1　準備

配布の OneShot.java と Talk.java を、作業フォルダ（net03）にコピーしてコンパイルします。フォルダの作り方は 付録 1-2、ターミナルの開き方は 付録 3 です。

javac -encoding UTF-8 OneShot.java Talk.java
  • javac … Java のソースをコンパイルする
  • -encoding UTF-8 … ソースファイルを UTF-8 として読む（日本語のコメントが化けないように）

何も表示されずにプロンプトに戻れば成功です。 OneShot.class と Talk.class ができています。javac と java の打ち方は 付録 4-3 にもあります。

Talk.java は、キーボードから打った行をサーバに送り、返事を1行表示するクライアントです。終わるときは Ctrl ＋ C を押します。

A-2　OneShot.java を読む

4つの動詞が1つずつ見えるように、あえて try-with-resources を使わずに書いてあります（演習Bで直します）。

ServerSocket server = new ServerSocket(port);      // (1) bind + listen
System.out.println("LISTENING port=" + port);

Socket s = server.accept();                        // (2) ここで止まる
System.err.println("ACCEPTED " + s.getRemoteSocketAddress());

BufferedReader in = new BufferedReader(
    new InputStreamReader(s.getInputStream(), StandardCharsets.UTF_8));
BufferedWriter out = new BufferedWriter(
    new OutputStreamWriter(s.getOutputStream(), StandardCharsets.UTF_8));

String line = in.readLine();                       // (3) 1行だけ読む
System.err.println("RECEIVED " + line);
out.write(line);
out.write("\n");                                   // 改行は自分で1バイト
out.flush();                                       // 第2回の教訓

s.close();                                         // (4) この1本を閉じる
server.close();                                    //     受付も閉じる

第2回でやったことが、そのまま入っています。 文字コードを書く、newLine() を使わない、flush() を忘れない。サーバ側でも同じです。

読んで分からない行があったら（必要な人だけ）、その行を選んで Copilot に /explain で聞いてください。聞き方と実例は 付録 5-6 にあります。この accept() の行の聞き方も、実例1 に載せてあります。

A-3　動かす（ターミナルを2枚使います）

LISTENING port=40001 と出たまま止まります。それが正常です。

# ターミナル(2)：確認とクライアント

  • netstat -an … 今あるTCPの口を、番号のまま一覧にする
  • | findstr 40001 … その中から、40001 を含む行だけを残す

netstat に、0.0.0.0:40001 か [::]:40001 の行が LISTENING で出ているはずです。

Talk が CONNECTED to localhost/127.0.0.1:40001 と出したら、hello と打って Enter を押します。

こう出れば正解です。

（ターミナル(2)）

A-4　確かめること

Checklist

  • ターミナル(2)で、送った行がそのまま返ってきた

PART 3演習B

何度でも受け付けるサーバ

B-1　LoopServer.java を作る

OneShot.java をコピーして LoopServer.java を作り、accept() をくり返しの中に入れます。 クラス名も LoopServer に変えてください。

Copy-Item OneShot.java LoopServer.java
  • Copy-Item A B … ファイル A を、B という名前でコピーする

main の中を、次のように書き換えます。

try (ServerSocket server = new ServerSocket(port)) {
  System.out.println("LISTENING port=" + port);

  while (true) {                                   // 1人ずつ、順番に
    try (Socket s = server.accept();
         BufferedReader in = new BufferedReader(
             new InputStreamReader(s.getInputStream(), StandardCharsets.UTF_8));
         BufferedWriter out = new BufferedWriter(
             new OutputStreamWriter(s.getOutputStream(), StandardCharsets.UTF_8))) {

      System.err.println("ACCEPTED " + s.getRemoteSocketAddress());

      String line;
      while ((line = in.readLine()) != null) {     // 相手が切断すると null になる
        out.write(line);
        out.write("\n");
        out.flush();
      }
      System.err.println("CLOSED");

    } catch (IOException e) {
      System.err.println("client error: " + e.getMessage());   // 落ちない
    }
  }
}
★ 実は、これが EchoServer.jar の中身です。 第1回・第2回であなたが接続していた相手は、ほぼこのコードでした。2回分の演習で使い続けたものが、40行に満たないプログラムだったということです。

B-2　くり返しのポイントは3つ

書き方なぜそうするか
while (true) の中に accept()1人終わったら、また受付に戻る
while ((line = in.readLine()) != null)相手が切断すると readLine() は null を返す。例外ではなく null
catch (IOException e) が while (true) の内側1人の失敗で、サーバ全体を終了させない。 外側に書くと、1人が回線を切っただけでサーバが止まる

readLine() が null を返すのがいつなのか分からない人は、付録 5-6 の実例2 の聞き方で Copilot に聞いて、自分で確かめてください（必要な人だけ）。

3つ目が、今日いちばん実務に近いポイントです。 クライアントは、いつ、どんな切れ方をするか分かりません。サーバは、それでも動き続けなければいけません。

B-3　動かして確かめる

# ターミナル(1)
javac -encoding UTF-8 LoopServer.java
java LoopServer 40001

# ターミナル(2)（何度でもくり返す）
java Talk localhost 40001

Talk で1行打って返事を見たら、Ctrl ＋ C で止めて、もう一度 java Talk localhost 40001。これを3回くり返します。

第2回の EchoClient.java がある人は、java EchoClient localhost 40001 JP UTF-8 でも試してください。第2回と同じ MATCH=true が、今度は自分のサーバから返ってきます。

こう出れば正解です（ターミナル(1)）。

LISTENING port=40001
ACCEPTED /127.0.0.1:34722
CLOSED
ACCEPTED /127.0.0.1:34728
CLOSED
ACCEPTED /127.0.0.1:34736
CLOSED

Checklist

  • クライアントを3回つないでも、サーバは動き続けている
  • ターミナル(1)の標準エラーに、ACCEPTED と CLOSED が3回ずつ出ている（CLOSED の代わりに client error: Connection reset と出ることもあります。Ctrl ＋ C で止めたときの切れ方の違いで、どちらも正常です）
  • ACCEPTED の行の最後の数字（相手のポート番号）が、毎回違う
★ 3つ目に注目してください。 /127.0.0.1:34722 のような表示のうち、最後の数字が実行のたびに変わります。 これは第1回の図2でやった、接続する側に OS が自動で割り当てた番号です。「誰も決めていないポート番号」を、初めて実物で見たことになります。

B-4　★ BindException を出す

ターミナル(3)を開いて、もう1つサーバを起動してください。 ターミナル(1)のサーバは起動したままにします。

# ターミナル(3)
java LoopServer 40001

こう出れば正解です。

Exception in thread "main" java.net.BindException: Address already in use

Windows では、Address already in use の後ろに : bind などが付くことがあります。

第1回で予告した例外に、ここで着きました。

  • 40001 番を確保しているプログラムは、この瞬間ただ1つです
  • 番号を変えれば、2つ同時に起動できます。 java LoopServer 40002 を試してください（試したら Ctrl ＋ C で止める）
  • 今日から、Address already in use を見たら「前に起動したサーバがまだ生きている」と読んでください

誰が 40001 を確保しているかは、次の3行で調べて止められます。

netstat -ano | findstr 40001
Get-Process -Id <いちばん右の数字>
Stop-Process -Id <いちばん右の数字>
  • netstat -ano … -an に加えて、-o でその口を使っているプロセスの番号（PID）を右端に出す
  • Get-Process -Id 番号 … その番号のプロセスの名前を見る（java と出るはず）
  • Stop-Process -Id 番号 … そのプロセスを止める

管理者権限は要りません。自分が起動したプロセスなら、自分で止められます。 ただし Stop-Process は、Get-Process で java だと確かめてから使ってください。

課題：LineServer.java（全2問）

1行受け取るたびに、1行返すサーバを作ります。演習Bの LoopServer.java に、受け取った行を見て、返す内容を変える処理を足していきます。

完成形

java LineServer <ポート番号>

起動すると、標準出力にこの1行だけを出して、待ち受けを続けます。

LISTENING port=40001

つないだ相手との、やりとりの例です。

問2何をされても、サーバは死なない（QUIT・切断・最後まで動き続ける）ケース6〜9
全問に共通： 返す1行の最後は 0x0A の1バイト（out.write("\n")）。文字コードは UTF-8 を明示。標準出力に出すのは LISTENING port= の1行だけで、ログはすべて System.err に出します。
問1コマンドに答える

やること

  • 受け取った1行が PING なら PONG を返す
  • ECHO <文字列> なら、<文字列> をそのまま返す（最初の半角スペースより後ろを全部）
  • LEN <文字列> なら、<文字列> を UTF-8 にしたときのバイト数を10進の整数で返す
  • それ以外は、すべて ERR unknown command を返す

実行例

Talk から日本語を打つと化けることがあるので、手元の確かめは半角英数字で行います（演習C）。LEN こんにちは → 15 は、採点スクリプトが UTF-8 で送って確かめます。

細かい決まり（採点で見ます）

受け取った行返す行理由

ECHO（後ろに何もない）ERR unknown commandECHO と LEN は、半角スペースの後ろに1文字以上要る

★ ここでつまずく：LEN は、第2回の回収です。 LEN こんにちは の答えは 15 です。5文字ですが、UTF-8 では 15バイトになります。第2回の課題で SEND_CHARS=5 ／ SEND_BYTES=16 と出したのを思い出してください。16 だったのは改行 0A も数えていたからで、今回の LEN は改行を含めません。

問2何をされても、サーバは死なない

やること

  • 1本の接続で、何行でも順に答える（readLine() を while でくり返す）
  • QUIT を受け取ったら BYE を返し、その接続だけを閉じる。サーバは待ち受けを続ける
  • 相手が何も言わずに切断しても、強制的に切断しても、サーバは次の accept() に戻る
  • 最後まで、標準出力は LISTENING port= の1行だけ。スタックトレースを出さない

守ること

Checklist

  • while (true) で、何人でも順に受け付ける
  • readLine() が null を返したら、その接続を閉じて次の accept() へ
  • catch (IOException e) は while (true) の内側に置く（1人の失敗でサーバを止めない）
  • System.exit() を呼ばない。QUIT で server.close() しない
  • スレッドを使わない（new Thread ／ ExecutorService は第4回）
★ ここが課題の中心：ケース7と8。 QUIT で閉じるのはその接続1本だけです。サーバごと終了させると、ケース7・8・9 がまとめて落ちます。

ケース8では、採点スクリプトがわざと乱暴に切断します。何も送らずに切る、改行の前で切る、返事を読まずに切る、いきなり強制切断する、の4通りです。catch が while (true) の外側にあると、強制切断の1回でサーバが止まります。
