この資料の使い方

この授業の開発環境の使い方を、1つにまとめた付録です。 毎回の授業資料から「付録の◯」とリンクで飛んできます。全部を読む必要はありません。 飛んできた節だけ読んで、授業資料に戻ってください。

  • エディタは VS Code、AI は GitHub Copilot、言語は Java です。
  • Java のプログラムは、VS Code の中のターミナルで javac → java と打って動かします。 ▷（実行）ボタンは使いません（理由は 4-4）。
  • この資料は JM教室のPC を前提に書いています。自分のノートPCでも同じ手順で動きます。

付録 1

VS Code を開いて、フォルダを用意する

1-1　VS Code を起動する

  1. VS Code を起動する。英語表示だったら、一度閉じて（右上の ×）もう一度起動する
    • 日本語表示になれば OK です。 ログオン直後の最初の起動だけ、英語表示になります。この資料の画面とボタンの名前は、日本語表示に合わせています
英語表示のまま使い続けないでください。 見た目だけでなく、サインインの情報を置く場所が違うため、あとで Copilot や GitHub がうまく動かないことがあります。

1-2　その回のフォルダを作って開く

  1. デスクトップに、その回のフォルダを作る。 名前は net ＋ 回の番号2桁にします（第3回なら net03）
  2. 配布の zip を展開して、中のファイルをそのフォルダにコピーする
    • zip の中から直接は動きません。 必ず展開してから使ってください
  3. VS Code の 「ファイル」→「フォルダーを開く」 から、そのフォルダを開く
  4. 「このフォルダー内のファイルの作成者を信頼しますか？」と出たら、「はい、作成者を信頼します」を押す
    • 自分で作ったフォルダなので、信頼して問題ありません。「いいえ」を選ぶと制限モードで開かれ、Copilot の提案が出なくなります。 間違えたら、VS Code を閉じて開き直してください
ここで確認　画面の左側（エクスプローラー）に、フォルダの名前（NET03 のように大文字で出ます）と、コピーしたファイルが並んでいれば成功です。
1回の授業で、1つのフォルダ。 前の回のフォルダに続けて作ると、同じ名前のファイル（Talk.java など）が混ざって、どれを動かしているのか分からなくなります。前の回のファイルを使うときは、今回のフォルダにコピーしてから使います。
提出するファイルは、授業の終わりに自分で持ち帰ってください。 教室のPCに残したファイルが、次の回にも残っているとは限りません。

付録 2

Copilot にサインインする

拡張機能が入っていても、サインインしていなければ Copilot は1文字も提案しません。「提案が出ない」の原因は、ほとんどがこれです。ログオフで消えるので、毎回の授業で必要です。

  1. 画面いちばん上、検索ボックスのすぐ右にある Copilot のアイコンをクリックする（Ctrl ＋ Alt ＋ I でも開きます）

VS Code のいちばん上にある Copilot のアイコン。「×」の印が付いていれば、サインインしていない状態です

  1. 右側にパネルが開き、「サインインして AI 機能を使用する」と出ます。いちばん上の青いボタン「GitHub で続行する」を押す

チャットのパネルのサインイン画面。押すのはいちばん上の「GitHub で続行する」です

  1. ブラウザが開くので、自分の GitHub アカウントでログインし、「Authorize Visual Studio Code」（承認）を押す
    • 二要素認証を設定している人は、ここでスマホの確認コードを求められます
  2. 「Visual Studio Code を開きますか？」と聞かれたら「開く」を選び、VS Code に戻る
ここで確認　パネルが文字の入力欄に変わり、Copilot のアイコンの「×」が消えていれば成功です。「GitHub で続行する」が出たままなら、サインインは終わっていません。
ここで間違えやすい3点 - 「Google で続行する」「Apple で続行する」は押さない。 GitHub アカウントをその方法で作った人だけの入口です。迷ったら「GitHub で続行する」です - 「Skip for now」は押さない。 Copilot が使えないまま先に進んでしまいます - サインインの画面すら出ないときは、Ctrl ＋ Shift ＋ P を押し、サインイン と打って 「GitHub Copilot: サインイン」 を選びます

付録 3

ターミナルを開く

この授業では、Java のプログラムを VS Code の中のターミナルで動かします。 ターミナルは、文字でコマンドを打ってPCを操作する画面です。中身は PowerShell です。

3-1　開き方

  • Ctrl ＋ Shift ＋ @ を押す
  • または、上のメニューの 「ターミナル」→「新しいターミナル」

画面の下にターミナルが開き、次のような行が出ます。

PS C:\Users\...\Desktop\net03>
  • PS … PowerShell であるという印
  • C:\Users\...\Desktop\net03 … いま、どのフォルダにいるか。1-2 で開いたフォルダになっています
  • > … この後ろにコマンドを打つ

... の部分は、PC やサインインした人によって違います。気にしなくて構いません。 見るのは、> の直前が、1-2 で開いたフォルダの名前（net03）になっているかだけです。授業資料のコマンドは、すべてこのフォルダで打つ前提です。

この資料では、この行を短くして PS ...\net03> と書きます。授業資料の実行例では、ここを省いて > だけにしていることがあります。

3-2　Java が使えるか確かめる

java -version
javac -version
  • java -version … Java のプログラムを動かす道具（java）の版を表示する
  • javac -version … Java のソースをコンパイルする道具（javac）の版を表示する

どちらも、17 以上の数字が出れば準備完了です。 出てくる文字は PC によって少しずつ違います。

javac 17.0.12
「認識されません」と出たら、Java が使えない状態です。その場で手を挙げてください。 自分で直そうとしなくて構いません。

3-3　ターミナルを2枚以上使う

サーバとクライアントを同時に動かすときは、ターミナルが2枚要ります（第3回の演習Cでは3枚）。

  1. 上のメニューの 「ターミナル」→「新しいターミナル」 を、もう一度押す
  2. ターミナルが増えると、ターミナルの右側に一覧が出ます。 クリックで切り替えます

どのターミナルで何を動かしているかを、自分で決めておいてください。 授業資料では「ターミナル(1)：サーバ」「ターミナル(2)：クライアント」のように書いています。

3-4　止める・やり直す

やりたいこと打つもの
動いているプログラムを止めるそのターミナルで Ctrl ＋ C
前に打ったコマンドをもう一度打つ↑ キーで呼び出して Enter
いまのフォルダにあるファイルを見るdir
いまどのフォルダにいるかを見るpwd
  • dir … いまいるフォルダの中のファイルを一覧にする
  • pwd … いまいるフォルダの場所を表示する
サーバを起動したターミナルは、何も表示せずに止まって見えます。 故障ではなく、誰かが接続してくるのを待っています。止めるときは Ctrl ＋ C です。

付録 4

Java のプログラムを作って、実行する

4-1　ファイルを作る

  1. 画面の左側（エクスプローラー）の、フォルダの名前の欄にマウスを乗せると出る「新しいファイル」のアイコンをクリックする
  2. Hello.java と打って Enter
    • デスクトップやメモ帳で作らないこと。 フォルダの外に作ると、Copilot が周りのファイルを読めません
ファイル名は、public class の後ろの名前と同じにします。大文字・小文字も同じです。 public class Hello なら Hello.java。違うと、コンパイルで止まります（6 うまくいかないとき）。

4-2　書いて、保存する

Hello.java に、次のように打ちます。

public class Hello {
  public static void main(String[] args) {
    System.out.println("Hello");
  }
}

Ctrl ＋ S で保存します。 保存していないファイルは、タブの名前の横に ● が付きます。● が付いたまま javac しても、直す前のファイルがコンパイルされます。

4-3　コンパイルして、動かす

ターミナルで、次の2行を打ちます。

javac -encoding UTF-8 Hello.java
java Hello
  • javac Hello.java … Hello.java をコンパイルして、Hello.class を作る
  • -encoding UTF-8 … ソースファイルを UTF-8 として読む（この授業では必ず付けます。 付けないと、日本語のコメントや文字列が化けることがあります）
  • java Hello … Hello.class を動かす。.class も .java も付けません

こう出れば正解です。

PS ...\net03> javac -encoding UTF-8 Hello.java
PS ...\net03> java Hello
Hello

javac は、うまくいったときは何も表示しません。 何か表示されたら、それはエラーです。エラーの1行目を読んでください。 何行目の何が悪いかが書いてあります。

引数を渡すときは、クラス名の後ろに半角スペースで区切って並べます。プログラムの中では args[0]、args[1]、… で受け取ります。

java OneShot 40001
java Talk localhost 40001

4-4　▷（実行）ボタンを使わない理由

Java の拡張機能が入っているので、ファイルの右上に ▷ のボタンが出ます。この授業では使いません。

  • 授業資料のコマンドを、そのまま打てる。 引数（ポート番号など）を渡す場面が毎回あります
  • 採点スクリプトと同じ方法で動かせる。 採点スクリプトも javac -encoding UTF-8 → java で動かします
  • 何を動かしているかが見える。 ターミナルに打った1行が、そのまま記録として残ります

拡張機能は、コードの間違いを赤い波線で教えてくれるところで役に立ちます。波線にマウスを乗せると理由が出ます。波線が残ったまま javac しても、同じエラーで止まります。

4-5　サーバとクライアントを両方動かす

ネットワークのプログラムは、相手がいて初めて動きます。 ターミナルを2枚使います（3-3）。

# ターミナル(1)：サーバ（先に起動して、そのままにしておく）
java OneShot 40001

# ターミナル(2)：クライアント
java Talk localhost 40001

先にサーバ、あとからクライアントの順です。逆にすると、クライアントは REFUSED（相手がいない）になります。

プログラムを直したら、動いている古いプログラムを Ctrl ＋ C で止めてから、javac → java をやり直します。止めないまま起動すると、Address already in use（その番号は使用中）で止まります。

付録 5

Copilot の使い方

5-1　この授業での決まり

Copilot を使って構いません。ただし、生成された行を説明できることが評価の対象です。

Checklist

  • Tab を押す前に、提案を読む。 読まずに押した行は、自分のコードではありません
  • 聞く前に15秒、自分の予想を立てる。 「たぶんここが原因」を先に考えてから聞きます
  • 答えは、自分で動かして確かめてから信じる。 Copilot は、間違えるときも正しいときと同じ口調で答えます
  • 完成品をまるごと作らせない。 課題の文章をそのまま貼って「作って」と頼むのは禁止です
  • 消す・上書きするコマンドを Copilot が出しても、自分では実行しない。 先生に見せてください
  • 学籍番号・氏名・パスワードを入力しない
  • 使った指示は prompt_log.md に記録する（書き方は各回の課題の節）
★「Copilot が書いたので分かりません」は通用しません。 提出したコードの、どの行について聞かれても説明できる状態にしてから提出してください。

5-2　① コメントを書いて Tab（インライン補完）

いちばんよく使う使い方です。 何をしたいかを日本語のコメントで書いて Enter を押すと、その下に薄いグレーの文字で提案が出ます。

public class Hello {
  public static void main(String[] args) {
    // 引数が1つあれば「こんにちは、◯◯さん」、なければ「こんにちは」と表示する
  }
}
キー何が起きるか
Tab提案を採用する
Esc提案を捨てる
Alt ＋ ]別の候補を見る。提案は1つではありません
ここで確認　グレーの文字が出れば、Copilot は動いています。何も出ないときは、①サインインしているか（2）②ファイル名が .java で終わっているか ③フォルダを信頼したか（1-2）の順に確かめます。

提案の良し悪しは、コメントの書き方で決まります。 Copilot に渡っているのは、開いているファイル、あなたのコメント、変数の名前、カーソルの周りのコードだけです。「何を」「どの形で」「どんなときにどうするか」まで書くと、提案が良くなります。 関係ないファイルのタブは閉じておきます。

5-3　② 選んで Ctrl ＋ I（インラインチャット）

直したいコードを選んでから Ctrl ＋ I を押すと、その場で日本語の指示が出せます。

文字コードを UTF-8 に指定するように直して

直した結果が、元のコードと比べて表示されます。 右上の ✓ で採用、× で取り消しです。

Ctrl + I で書き足されたコードと、採用（✓）・取り消し（×）のボタン。画面のコードは別の言語の例です

✓ を押す前に、どこが変わったかを必ず目で追ってください。 ここを読まずに ✓ を押す癖がつくと、自分のコードが読めなくなります。

「Auto mode failed: selected model '' not found in known endpoints.」と出たら、サインインがうまく引き継がれていません。故障ではありません。 一度サインアウトして、サインインし直すと直ります。

サインアウトは、画面左下の人型のアイコン（アカウント）→ 自分の GitHub ユーザー名にマウスを乗せる → 「サインアウト」です（下の画像）。そのあと 2 Copilot にサインインする の手順で、もう一度サインインします。

Ctrl + I の欄で頼んだときに出るエラーの例

アカウントのメニューからサインアウトする。右に開くメニューのいちばん下です

5-4　③ チャットで聞く（/explain・/fix）

Ctrl ＋ Alt ＋ I で、右側にチャットのパネルが開きます。日本語で質問できます。先頭に決まった記号を付けると、何をしてほしいかが正確に伝わります。

打つもの使う場面例
/explainコードの意味が分からないとき。コードを選んでから打つ/explain 初心者にも分かるように、1行ずつ日本語で説明して
/fixエラーが出たとき。エラーの全文を貼る/fix 実行するとこのエラーが出ます：（ここにエラーの全文）
  • /explain は、コードを1文字も書き換えません。 安心して使ってください。意味の分からない行を見つけたら、その場で /explain を習慣にします
  • /fix には、エラーメッセージを省略せずに全部貼ります。「なんかエラーが出ます」だけでは、推測しか返ってきません
  • /fix の直し方を採用する前に、「なぜこれで直るのか」を /explain で聞いてください。 理由を言えない修正は採用しません
ネットワークのプログラムで、Copilot が見つけられないもの。 「固まる」「返事が来ない」は、エラーが出ません。エラーが出ないものは /fix に貼れません。どこで止まっているかは、自分で System.err.println を入れて確かめます。 この授業の大事な部分は、ここにあります。

5-5　④ Agent モードについて

チャットのパネルの上のほうで、モードを Agent に切り替えると、ファイルを作ったりコマンドを実行したりまで、まとめて自動でやってくれます。

この授業では、課題のプログラムを Agent モードで作らせないでください。 何をされたかが追いにくく、提出したコードを説明できなくなるからです（5-1 の「完成品をまるごと作らせない」）。

チャットと Agent モードは、使える回数に上限があります。 無料の Copilot Free では、チャット・Agent モードの「プレミアムリクエスト」は月50回までです（コメント → Tab の補完は、ほぼ気にせず使えます）。コメント → Tab と /explain を中心に使ってください。 使った回数は https://github.com/settings/copilot で確かめられます。

5-6　プログラムが分からないときの聞き方（必要な人だけ・実例つき）

必須ではありません。 配布されたコードや、Copilot が出したコードの中に分からない行があったときに使ってください。実例は、第3回の OneShot.java と LoopServer.java です。

聞くときは、いつもこの順番です。

  1. 分からない行を、1〜3行だけ選ぶ。 ファイルまるごと選ぶと、答えがぼやけます
  2. 聞く前に15秒、自分の予想を立てる。「たぶんここで待っている」くらいで構いません
  3. /explain で聞く。「何をするか」だけでなく、「なぜ」「いつ」「どうなると壊れるか」まで聞きます
  4. 答えを、自分で動かして確かめる。 確かめるまでは、答えを信じません
  5. 役に立った聞き方は、prompt_log.md に記録する

実例1　accept() の行で、何が起きているのか分からない

OneShot.java の次の1行を選んで、チャットに打ちます。

Socket s = server.accept();                        // (2) ここで止まる
/explain この1行で何が起きますか。プログラムがここで止まるのはなぜですか。止まっているあいだ、何を待っていますか

答えの例（Copilot の答えは、毎回少しずつ違います。要点だけ）

accept() は、クライアントが接続してくるまで、そこで待ち続けます（ブロックする）。接続が来ると、その相手と通信するための新しい Socket を作って返します。 待っているあいだ、プログラムは次の行に進みません。

確かめ方　java OneShot 40001 を起動したまま何もしないと、ACCEPTED は出ません。別のターミナルで java Talk localhost 40001 を実行した瞬間に、ACCEPTED が出ます。答えのとおりに動いたら、納得して先へ進みます。

実例2　くり返しが、いつ終わるのか分からない

LoopServer.java の次の行を選びます。

while ((line = in.readLine()) != null) {     // 相手が切断すると null になる
/explain この while はいつ終わりますか。readLine() が null を返すのはどんなときですか。例外が出るときとの違いも教えて

答えの例（要点）

readLine() は、1行を読むまで待ちます。相手が接続を閉じると、それ以上読むものがないので null を返し、くり返しが終わります。相手が強制的に切ったときなどは、null ではなく IOException が出ることがあります。

確かめ方　LoopServer に Talk でつなぎ、Talk を Ctrl ＋ C で止めます。サーバの画面に CLOSED（または client error: ...）が出れば、答えのとおりです。

実例3　エラーが出た（/fix の答えを、そのまま信じない）

2つ目の LoopServer を起動したら、次のエラーが出たとします。エラーは全文を貼ります。

/fix 実行するとこのエラーが出ます：
Exception in thread "main" java.net.BindException: Address already in use

「ポート番号を 40002 などに変える」と提案されることがあります。 これは、この授業では正しい直し方ではありません。 原因は、前に起動したサーバが、まだ 40001 を使っていることです。番号を変えると、採点スクリプトが 40001 につなげなくなります。

正しい直し方は、前のサーバを Ctrl ＋ C で止めることです（第3回の資料 B-4）。AI の答えは「エラーが消える方法」であって、「授業の決まりに合う方法」とは限りません。 そこを確かめるのは、あなたの仕事です。

実例4　書き方の違いが分からない（コードを選ばずに聞く）

チャットに、そのまま打ちます。

Java で、ソケットに文字を書くとき、PrintWriter(s.getOutputStream(), true) と
new OutputStreamWriter(s.getOutputStream(), StandardCharsets.UTF_8) は何が違いますか。
文字コードの点から、初心者にも分かるように説明して

答えの例（要点）

PrintWriter(OutputStream, boolean) は、文字コードを指定できず、PC の既定の文字コードで書きます。 送る側と受ける側で既定が違うと、日本語が化けます。OutputStreamWriter に StandardCharsets.UTF_8 を渡すと、どの PC でも UTF-8 で書けます。

確かめ方　第2回でやった「文字コードが違うと化ける」を思い出してください。この授業で PrintWriter(OutputStream) を使わない理由は、これです。
